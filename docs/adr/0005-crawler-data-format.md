# ADR 0005: クローラーとのデータの受け渡しを、標準出力の JSON Lines（v1）で行う

ステータス: 採択

## 文脈

epubize はクローラーを子プロセスとして起動し、結果を受け取る（ADR 0004）。
クロールの頻度は epubize が管理するため、クローラーのコマンド 1 回が、1 回の取得に対応している必要がある。
受け渡しの仕様は公開してよく、データを使う epubize の側が持つ。

## 実装すること

- 受け渡しの仕様は JSON Schema として `schema/crawler-output.v1.schema.json` に置く。クローラーはこれに合わせる
- クローラーは次のコマンドを持ち、標準出力に 1 行 1 レコードの JSON（JSON Lines）を書く
  - `toc <作品URL>`：`novel` レコード 1 行と、目次の順に `toc_entry` レコードを出す。本文は取らない
  - `episode <話URL>`：`episode` レコード 1 行を出す
  - `image <画像URL>`：`image` レコード 1 行を出す。画像のバイト列は base64 で入れる
- 失敗したときは `error` レコードを 1 行出し、0 以外の終了コードで終わる。`kind` は `unsupported_url`、`not_found`、`forbidden`、`rate_limited`、`server_error`、`http_error`、`network`、`parse_error` のいずれかとする。再試行するかどうかは epubize が `kind` で決める
- 各レコードは版 `v`（いまは 1）と種類 `type` を持つ。読む側は知らない項目を無視する。項目の追加では `v` を上げず、項目の削除や意味の変更のときだけ上げる
- 日時は UTC からの時差を含む ISO 8601 とする
- 改稿を検知するため、`toc_entry` は公開日時 `publishedAt` と、サイトが示す場合は改稿日時 `revisedAt` を持つ
- 本文、前書き、後書きは CommonMark で渡す。規約は次のとおりとする
  - 元の 1 行を、1 つの段落にする
  - 空行は、`<br>` だけの行で表す
  - ルビは HTML の `<ruby>` 要素をそのまま埋め込む（`<rb>`、`<rt>`、`<rp>` を含みうる）
  - 傍点などの強調は `*…*`、太字は `**…**` とする
  - 挿絵は `![代替テキスト](絶対URL)` とし、その URL は `episode` レコードの `images` に含める
- `charCount` は、本文をプレーンテキストにしたときの Unicode のコードポイント数とする

## 実装しないこと

- 複数の作品や複数の話をまとめて 1 回のコマンドで取ることはしない
- クローラーとの受け渡しに、ファイルや共有の SQLite を使うことはしない
- Markdown にルビの独自記法（`｜漢字《かんじ》` など）は使わない

## テスト設計

- 方針と仕様の決定であり、epubize の側ではこの時点ではコードを伴わないため、テストはない
- クローラーの側で、出力がこの JSON Schema に合うことをテストする
- 取り込みを実装するときに、各レコードを JSON Schema で検証してから保存することをテストする

## トレードオフ

- 目次と本文を別のコマンドに分けるため、1 作品を取り込むのにプロセスを何度も起動する。その代わり、取得の 1 回ずつを epubize のキューで管理できる
- 挿絵を base64 で渡すため、データ量が元の約 4/3 になる
- ルビを HTML で埋め込むため、Markdown としての可読性は落ちる。その代わり、ルビの構造を失わずに XHTML へ変換できる

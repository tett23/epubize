# ADR 0018: 取得した結果を検証して保存し、続く取得を積み、画面をデータベースから読む

ステータス: 採択

## 文脈

スキーマ（ADR 0017）ができたので、取得した結果を保存し、画面のボタンをつなぐ。
fetch all と fetch all metadata の働きは kindlize と同じにする。fetch all metadata は全作品の目次だけを、fetch all は目次に続けて、未取得の話と改稿された話の本文と挿絵までを取得する。
画面は合成データ（ADR 0011）を表示していたが、取得した結果を見られるよう、データベースから読むように切り替える。
クローラーの実行ファイルは、設定画面を作るまでの仮の方法として、環境変数 `EPUBIZE_CRAWLER` で指定していた（ADR 0016）。利用者の求めで、PATH から探すようにする。

## 実装すること

- クローラーの実行ファイルは、次の順に探す。設定画面を作るときに改める
  - 環境変数 `EPUBIZE_CRAWLER`（テストで偽のクローラーを使うために残す）
  - PATH にある `novel-crawler`
  - `~/bin`、`~/.local/bin`、`/opt/homebrew/bin`、`/usr/local/bin` にある `novel-crawler`。Finder から起動したアプリはシェルの PATH を引き継がないため
- これにより、ADR 0016 の「PATH からクローラーを探さない」を改める。ADR 0016 は、そのほかの決定が生きているため、ステータスを採択のまま残す
- クローラーの標準出力は、1 行ずつ JSON Schema（`schema/crawler-output.v1.schema.json`、形式の検査を含む）で検証してから読む。合わない行が 1 つでもあれば、どの行かを示して保存しない（ADR 0005 のテスト設計）
- 保存する日時は UTC に揃える。改稿の検知で、日時を文字列のまま比べるため
- 目次（`toc`）の結果の保存
  - 作品は購読と同じ `site` と `site_id` で対応させ、取り直したら同じ行を書き換える
  - 話は URL で対応させ、位置、題名、章、公開日時、改稿日時を書き換える。目次の順が変わっても、取得済みの本文は残る
  - 目次から消えた話は消す
- 話（`episode`）の結果の保存では、本文と、本文を取得したときの改稿日時を書き、話と挿絵の対応を入れ直す
- 挿絵（`image`）の結果の保存では、base64 を戻した長さが `byteLength` と合わなければ保存しない
- 取得の要求に「続く取得を積むか」（`follow_up`）を持たせ、結果を保存した後に続く取得を積む
  - 目次の後には、未取得か、目次の改稿日時が本文を取得したときより新しい話の本文の取得を積む
  - 話の後には、まだ持っていない挿絵の取得を積む
- ボタンの働き
  - fetch all：全てのキューを破棄し、購読の全作品の目次を、続く取得を積む形で積む
  - fetch all metadata：全てのキューを破棄し、購読の全作品の目次だけを積む
  - 未取得の add：その作品の目次だけを積む（kindlize の add）
  - 作品の fetch：その作品の目次を、続く取得を積む形で積む
  - 話の refetch：その話の本文を、続く取得を積む形で積む
  - 作品の remove episodes：確かめた後、その作品の話を全て消す。作品と挿絵は残す
  - download、send to Kindle は、まだ押せないまま置く
- 画面は、作品の一覧、latest、作品、話の全てをデータベースから読む。取得が終わるたび（`fetch-done`）に読み直す。続けて終わったときは、読み直しを 0.5 秒まとめる
- 一覧と目次では本文の列を読まない。本文は話のページでだけ読む
- 話のページのプレビューでは、挿絵をデータベースから data URL で読む。取得していない挿絵は、外部へ読みに行かないよう `src` を外して代替テキストだけを残す
- 整形の設定は、作品のページと話のページで、変えるたびにデータベースに保存する（ADR 0017）。保存を待たずに画面へ反映する
- 合成データ（`src/sampleData.ts`）は消す

## 実装しないこと

- 同じ挿絵を複数の話が参照しているとき、取得を 1 回にまとめることはしない。話を保存した時点で挿絵を持っていなければ、話ごとに積む
- 取得の失敗を保存しない。失敗は `fetch-done` で画面に知らせるだけにする
- 整形の設定を本文に適用することは、まだしない
- download、send to Kindle、mobi は実装しない
- クローラーを探した結果を、起動の後に探し直すことはしない。クローラーを置いた後は、アプリを起動し直す

## テスト設計

- `src-tauri/src/fetch/crawler.rs`：実行ファイルを、並べた場所の順に探し、実行できないファイルを飛ばすこと
- `src-tauri/src/library/records.rs`：各レコードを読むこと、知らない項目を無視すること、`isConcluded` がなくてもよいこと、JSON Schema に合わない行（項目の欠け、日時の形式、`v`、知らない `type`、JSON でない行）を、行の番号を示して拒むこと
- `src-tauri/src/library/store.rs`：日時を UTC に揃えること、目次を保存して取り直すと同じ行を書き換えること、目次の順が変わっても本文が残り、消えた話が消えること、作品のレコードが 1 つでない目次を拒むこと、未取得と改稿された話を挙げること、話を保存してまだ持っていない挿絵を挙げること、目次にない話を拒むこと、挿絵の長さの検査
- `src-tauri/src/library/query.rs`：一覧の数、作品の詳細、話の詳細で取得済みの挿絵だけを data URL にすること、latest、整形の設定の保存と既定への戻し、話の削除
- `src-tauri/src/pipeline.rs`：目次の後に本文を、話の後に挿絵を積むこと、`follow_up` が偽なら積まないこと、挿絵を持った後には積まないこと、スキーマに合わない出力を拒むこと
- `src/lib/library.test.ts`、`src/lib/markdown.test.ts`：一覧の数、日付と章のまとめ方、前後の話、挿絵の差し替えと、取得していない挿絵を読みに行かないこと
- 合成データを返す偽のクローラーを `EPUBIZE_CRAWLER` に指定して debug ビルドの `.app` を起動し、computer-use で次を確かめた
  - 未取得の add で目次だけが保存され、作品が一覧に出て、未取得から消えること
  - fetch all で目次、本文、挿絵の順に取得され、同じドメインの取得は 5 秒空くこと
  - 作品のページに文字数の合計、完結済み、章ごとの目次が出ること
  - 整形の設定を変えるとデータベースに保存され、話のページに移っても保たれること
  - 話のページのプレビューに、データベースの挿絵が表示されること。refetch で本文を取り直し、持っていない挿絵だけを取得すること
  - latest に、公開日ごとに話が並ぶこと

## トレードオフ

- 目次から消えた話を消すため、サイトで消された話の本文は手元にも残らない。その代わり、目次とデータベースの話がずれない
- 出力の 1 行でもスキーマに合わなければ、その取得の結果を全て捨てる。その代わり、壊れた値を保存しない
- 挿絵を話ごとに積むため、同じ挿絵を何度か取得することがある
- 画面を取得のたびに読み直すため、取得の多いときは読み出しが増える。0.5 秒まとめて抑える
- クローラーを決まった場所からも探すため、PATH にないクローラーを使ってしまうことがある。設定画面で指定できるようにするまでの制約とする

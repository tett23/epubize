# ADR 0007: メインウィンドウの位置と大きさを記録して次の起動時に戻し、画面に収まらなければ既定の位置に出す

ステータス: 採択

## 文脈

起動するたびにウィンドウを動かし直すのは手間なので、前回の位置と大きさで開きたい。
一方、ディスプレイを外したり配置を変えたりすると、記録した位置が画面の外になり、ウィンドウを操作できなくなる。

Tauri の公式プラグイン `tauri-plugin-window-state` は位置と大きさを戻せるが、次の点が要求に合わない。

- ウィンドウの四隅のどれか一つでもディスプレイに載っていれば、記録した位置に戻す。タイトルバーが画面の外にあっても戻してしまう
- 位置を戻さないときは OS に任せ、設定した既定の位置にはしない
- 大きさは、ディスプレイに収まるかに関わらず戻す

## 実装すること

- `src-tauri/src/window_state.rs` に、記録と復元を自前で実装する
- 記録するのは、枠を含む位置と大きさ（判定用）と、枠を除く大きさ（復元用）とし、物理ピクセルで持つ
- 移動と大きさの変更のたびにメモリ上の値を更新し、ウィンドウを閉じるときとアプリの終了時に、アプリ用設定領域（`app_config_dir`）の `window-state.json` に書き出す
- 最大化、最小化、全画面のときの位置と大きさは記録しない
- 起動時に、記録したウィンドウの全体が、いずれかのディスプレイの上にあるかを判定する。複数のディスプレイにまたがっていてもよい
  - 全体が載っていれば、位置を移してから大きさを戻す
  - 一部でも載らなければ、位置も大きさも戻さず、`tauri.conf.json` の既定（800×600、画面の中央）のままにする
- 既定の位置から動いて見えないよう、ウィンドウは隠した状態で作り、復元してから表示する

## 実装しないこと

- `tauri-plugin-window-state` は使わない
- 最大化や全画面の状態は戻さない
- 記録を SQLite（ADR 0003）には入れない。作品のデータではなく、壊れても既定に戻るだけの UI の状態であるため、ファイルに分ける
- 判定にはディスプレイの全域を使い、メニューバーや Dock を除いた作業領域は使わない。Dock の裏に一部が隠れる程度は許す

## テスト設計

- 判定の関数 `fits_on_monitors` を単体テストする
  - 一つのディスプレイに収まる場合、ディスプレイと同じ大きさの場合
  - 外したディスプレイの上にあった場合、一部がはみ出す場合、ディスプレイより大きい場合
  - 隣り合うディスプレイにまたがる場合、ずれて並んだディスプレイの隙間にかかる場合
  - 原点が負のディスプレイ、ミラーリングで同じ範囲のディスプレイが重なる場合
  - ディスプレイがない場合、大きさが 0 の場合
- 記録が JSON を通して元に戻ることをテストする
- 実際に起動して、記録した位置と大きさで開くこと、画面外の記録では既定の位置と大きさで開くこと、閉じたときに記録が書き出されることを確認した

## トレードオフ

- 公式プラグインより実装と保守の手間が増える。その代わり、画面外の判定と既定の位置への戻し方を要求どおりにできる
- 少しでもはみ出すと既定に戻るため、意図して画面の端からはみ出させた配置は戻らない
- 物理ピクセルで持つため、表示倍率の異なるディスプレイの間では、論理的な大きさが変わって見えることがある

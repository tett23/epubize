# ADR 0011: GUI の画面を kindlize の画面にならって作り、まず合成データで画面だけを実装する

ステータス: 採択

## 文脈

ADR 0001 では、以前の `kindize`（kindlize）のコードや設計を引き継がないとした。
一方、kindlize の管理画面は使い慣れており、画面の構成はそのまま使いたいと利用者が望んだ。
epubize には、まだ SQLite（ADR 0003）も、クロールのキュー（ADR 0004）も、EPUB の生成もない。
クローラーは本文を正規化して渡し、epubize は同じ正規化を重ねない（ADR 0009）。

## 実装すること

- 画面の構成と機能の並びを kindlize にならう。コードは引き継がず、新しく書く。余白などの見た目は Tailwind CSS（ADR 0008）で整える
  - トップ（`/`）：作品の URL の追加、fetch all と fetch all metadata、作品数・話数・未取得の話数と取得時間の目安、作品の一覧（最新話の日時、作品 ID、作者、題名、取得済み / 全話）、購読しているが未追加の作品（未取得）
  - latest（`/episodes/latest`）：全作品の話を公開日時の新しい順に 100 件、公開日ごとに区切って並べ、refetch と send to Kindle を置く
  - 作品（`/novels/:novelId`）：題名、作者、あらすじ、更新日・文字数・完結済み、fetch・remove episodes・download zip / epub / mobi・send to Kindle、整形の設定、章ごとの目次
  - 話（`/novels/:novelId/:episodeId`）：題名、操作のボタン、更新日、前後の話へのリンク、整形の設定、本文のプレビュー（縦書き / 横書き）、元の Markdown
- この段階では画面だけを作る。データは `src/sampleData.ts` の合成データとし、画面は `src/data.ts` を通して読む。SQLite を実装したら `src/data.ts` を Tauri のコマンドの呼び出しに置き換える
- 操作のボタンは、裏の機能ができるまで押せない状態で置く
- 整形の設定は kindlize と同じ項目を作品ごとに持つ。いまはメモリ上だけに持つ。プレビューに反映するのは組方向（vertical / horizontal）だけとする
- 画面の切り替えは react-router の `MemoryRouter` で行う。URL バーのないデスクトップアプリなので、履歴をブラウザの URL に結び付けない
- 本文の Markdown（ADR 0005・ADR 0009）は marked で HTML にし、DOMPurify で許した要素と属性（ルビ、傍点の `style`、強調など）だけを残してから表示する
- サイトや作者のページへのリンクは、`tauri-plugin-opener` で既定のブラウザに開く。アプリのウィンドウの中では開かない
- フロントエンドの単体テストは vitest で書き、`pnpm test` で `src/` の下だけを動かす。DOM が要るテストは jsdom で動かす

## 実装しないこと

- 追加、取得、削除、ダウンロード、Kindle への送信の機能は、この段階では実装しない
- 整形の設定を本文に適用することはしない。ADR 0009 との関係を含め、EPUB の生成を実装するときに決める
- 整形の設定を保存することはしない。再起動すると既定に戻る
- 合成データに、実在の作品の題名、作者名、本文を使わない

## テスト設計

- `src/lib/library.test.ts`：作品数・話数・未取得の話数と時間の目安の計算、作品の並び順、latest の並び順と日付ごとのまとめ方と件数の制限、前後の話の探し方（端では null）をテストする
- `src/lib/markdown.test.ts`：題名・前書き・本文・後書きのつなぎ方、ルビと傍点の HTML が残ること、強調と太字の変換、スクリプトとイベント属性が取り除かれることをテストする
- 内蔵ブラウザで 4 つの画面を開き、画面の切り替え、縦書きと横書きのプレビュー（ルビ、傍点、区切り線）、ダークモードの表示を確認した

## トレードオフ

- ADR 0001 の「設計を引き継がない」に対し、画面の構成だけは引き継ぐ。その代わり、使い慣れた操作のまま移れる
- 押せないボタンが並ぶため、機能ができるまでは画面が実際より多くのことをできるように見える
- 合成データを画面のコードと同じ場所に置くため、SQLite に移るときに読み出しの入口を差し替える手間がかかる。入口を `src/data.ts` の 1 か所にして手間を抑える
- 整形の設定を表示だけして適用しないため、設定を変えてもプレビューの組方向以外は変わらない

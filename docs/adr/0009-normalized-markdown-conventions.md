# ADR 0009: クローラーから受け取る本文の Markdown を、縦書き向けに正規化された形とする

ステータス: 採択

## 文脈

ADR 0005 では、クローラーが渡す本文の Markdown の規約を、元の HTML の段落・空行・字下げをそのまま残す形で決めた。傍点は `*…*` とした。
Web 小説は作者ごとに書き方がまちまちで、そのままでは本として読みにくい。
以前作った tett23/kindlize の `packages/normalize` には、縦書きの本にするための正規化の規則がある。クローラーはこれを参考に本文を正規化する（クローラーの ADR 0017）。

## 実装すること

- ADR 0005 の Markdown の規約のうち、次を置き換える。本文・前書き・後書きの全てに当てはまる
  - 空行：段落の間に 1 つだけある空行は消え、空行は 2 つまでになる。空行は引き続き `<br>` だけの行で表す
  - 字下げ：段落の先頭の空白は取り除かれ、括弧（`（「『〔［｛【〈` など）で始まらない段落には全角スペースが 1 つ入る
  - ルビ：`<ruby>親文字<rp>(</rp><rt>読み</rt><rp>)</rp></ruby>` の形に揃う
  - 傍点：`<span style="text-emphasis: sesame; -webkit-text-emphasis: sesame;">…</span>` で表す。`*…*` は傍点以外の強調に使う
  - 文字：半角の括弧と `! ?` は全角に、`！！ ？？ ！？ ？！` は `‼ ⁇ ⁉ ⁈` に、英大文字と数字だけの語は全角に、`か゛` のような濁点は結合した形になる
  - リンク：本文にリンクは含まれない。リンクだった文字はそのまま残る
- epubize は、受け取った本文をそのまま EPUB に使う前提とし、同じ正規化を重ねて行わない
- JSON Schema（`schema/crawler-output.v1.schema.json`）は変えない。本文の中身の規約だけの変更であり、レコードの形は変わらないため、`v` も上げない

## 実装しないこと

- 括弧で始まる段落にクラスを付けることはクローラーに求めない。必要なら epubize が表示するときに判断する
- 正規化を元に戻す（元の字下げや空行を復元する）ことはしない

## テスト設計

- 規約の決定であり、epubize の側ではこの時点ではコードを伴わないため、テストはない
- クローラーの側で、規則ごとのテストと、スキーマに合うことのテストを行っている（クローラーの ADR 0017）

## トレードオフ

- 元の字下げや段落の間の空行は epubize に届かない。作者の意図した書き方も揃えられてしまう
- 規則は縦書きを前提にしている。横書きで表示する場合、英数字の全角化などが不要な変換になる

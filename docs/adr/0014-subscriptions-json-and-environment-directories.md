# ADR 0014: 購読している作品を novels.json に持ち、データの置き場所を development と production に分ける

ステータス: 採択

## 文脈

作品の追加フォームを実装する。kindlize は購読している作品の ID を `~/.config/kindlize/<NODE_ENV>/novels.json` に、サイトごとの配列として持っていた。
利用者は、購読の一覧を SQLite ではなくこの形のファイルで持ちたい。ファイルを持ち運んだり、手で直したりできるためである。
また、開発中の版と普段使う版を同じ計算機で動かすため、データを分けておきたい。
ADR 0013 では SQLite をアプリ用データ領域の直下に、ADR 0007 ではウィンドウの位置と大きさの記録をアプリ用設定領域の直下に置くとしていた。

## 実装すること

- 環境は `development` と `production` の二つとする。環境変数 `EPUBIZE_ENV` があればそれに従い、なければ debug ビルドを `development`、release ビルドを `production` とする。それ以外の値ではエラーにする
- 購読している作品は `~/.config/epubize/<環境>/novels.json` に持つ。`XDG_CONFIG_HOME` があれば `~/.config` の代わりにそれを使う
- `novels.json` の形は kindlize と同じとする。`subscribe` の下に、サイト（`narou`、`novel18`、`hameln`、`kakuyomu`）ごとに作品 ID の配列を持つ。hameln の ID は数値、ほかは文字列とする
- `novels.json` の `subscribe` 以外のキーは読まず、書き換えるときもそのまま残す。キーの順番も保つ
- 作品の追加では、次のようにしてファイルが壊れないようにする
  - 書き換える前に、元のファイルを `novels.json.bak` に写す
  - 一時ファイル `novels.json.tmp` に書いてから、名前を変えて置き換える
  - すでに購読している作品なら、ファイルにもバックアップにも触れない
  - JSON として読めないとき、または形が想定と違うときは、エラーにしてファイルに触れない
- ファイルがなければ、ディレクトリごと作る
- 作品の URL からサイトと作品 ID を取り出す。作品の中の話の URL でもよい
- SQLite は `<アプリ用データ領域>/<環境>/epubize.sqlite3` に置く。これにより ADR 0013 のデータベースの置き場所を変える。マイグレーションの CLI も同じ規則で場所を決める
- ウィンドウの位置と大きさの記録は `<アプリ用設定領域>/<環境>/window-state.json` に置く。これにより ADR 0007 の記録の置き場所を変える
- ADR 0007 と ADR 0013 は、置き場所のほかの決定が生きているため、ステータスを採択のまま残す
- 画面の追加フォームは、Tauri のコマンド `add_subscription` を呼び、加えたか、すでに購読していたか、エラーの理由を表示する
- 画面の見出しには、Tauri のコマンド `environment` で得た環境を表示する。フロントエンドのビルドの種類（Vite の `MODE`）は、debug ビルドの `.app` でも `production` になり、データの置き場所と一致しないため使わない。Tauri の外で開いたときだけ `MODE` を表示する
- トップの「未取得」は、`list_subscriptions` で読んだ購読のうち、作品として追加していないものを表示する。作品の一覧はまだ合成データ（ADR 0011）なので、いまは購読の全てが並ぶ

## 実装しないこと

- 購読の一覧を SQLite に入れることはしない
- 作品の追加で、作品の情報を取得することはしない。取得はクロール（ADR 0004）を実装するときに行う
- 購読の解除は、この ADR では作らない
- `novels.json.bak` は 1 世代だけ持ち、追加のたびに上書きする
- 古い置き場所（アプリ用データ領域と設定領域の直下）のデータベースとウィンドウの記録は移さない。データベースにはまだスキーマがなく、ウィンドウの記録は失っても既定の位置に戻るだけであるため

## テスト設計

- `src-tauri/src/environment.rs`：変数がなければビルドの種類に従うこと、変数がビルドの種類より優先されること、知らない値を拒むこと
- `src-tauri/src/subscriptions.rs`：
  - 各サイトの作品と話の URL から、サイトと ID を取り出せること。対応していない URL を拒むこと。作った URL を読み戻せること
  - 購読の一覧をサイトの順に読むこと、ファイルがなければ空とすること
  - 追加の前の内容が `.bak` に残ること、一時ファイルが残らないこと
  - ほかのキーと、その順番が残ること。hameln の ID が数値で書かれること
  - すでに購読していれば書き換えず、`.bak` も作らないこと。数値の ID と文字列の ID を同じものとみなすこと
  - ファイルもディレクトリもなければ作ること
  - 壊れた JSON や形の違うファイルでは、エラーにしてファイルに触れないこと
  - 環境ごとに置き場所が分かれること
- `src-tauri/src/db/mod.rs`：データベースの置き場所が環境ごとに分かれること
- 内蔵ブラウザで Tauri のコマンドを差し替え、追加、すでに購読している場合、対応していない URL の場合の表示と、追加の後に未取得の一覧を読み直すことを確認した
- debug ビルドの `.app` を起動し、computer-use でウィンドウを操作して次を確認した
  - データベースが `development` の下に作られ、見出しに `development` と表示されること
  - ウィンドウを動かして終了すると `development/window-state.json` に記録され、起動し直すと同じ位置と大きさで開くこと
  - フォームから narou と hameln の作品を加えると、`~/.config/epubize/development/novels.json` に書かれ、hameln の ID が数値になり、`.bak` に追加の前の内容が残ること
  - 購読済みの作品の話の URL では「すでに購読しています」と表示され、ファイルも `.bak` も変わらないこと
  - 対応していない URL ではエラーが表示され、入力が残ること
  - 加えた作品のうち作品の一覧にないものが、「未取得」に表示されること

## トレードオフ

- 購読の一覧と作品のデータが別の場所に分かれるため、両者がずれることがある。その代わり、購読の一覧を手で直したり、kindlize のファイルをそのまま使ったりできる
- `subscribe` 以外のキーをそのまま残すため、kindlize のファイルにある送信の設定なども、epubize が使わないまま残る
- 環境を分けるため、development で追加した作品は production には現れない

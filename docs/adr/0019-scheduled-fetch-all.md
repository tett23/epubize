# ADR 0019: アプリが動いている間、毎日 3 時に fetch all を行う

ステータス: 採択

## 文脈

購読している作品の新しい話を、手で fetch all を押さなくても取り込みたい（ADR 0018）。
定期的に行うかどうかと、行う時刻は、後で作る管理画面で設定できるようにする予定である。
macOS では、計算機がスリープしている間、tokio の時間が進まないことがある。そのため、決めた時刻まで眠る方法では、時刻を大きく過ぎてから動いたり、取りこぼしたりする。

## 実装すること

- アプリが動いている間、毎日 3:00（ローカル時刻）に fetch all を行う。働きはボタンの fetch all と同じとし、全てのキューを破棄してから積み直す（ADR 0015、ADR 0016、ADR 0018）
- 定期取得の設定（行うか、時刻）は `src-tauri/src/schedule.rs` の `Schedule` に持つ。管理画面ができるまでは、既定値（行う、3:00）を使う
- 壁時計を 1 分ごとに見て、前に見たときから 3:00 を越えていれば行う
  - スリープなどで 3:00 を過ぎていた場合は、起きた後に最初に見たときに行う
  - 何日も眠っていても、起きた後に行うのは 1 回とする
  - 時計が戻ったときは行わない
  - アプリを起動した時点では行わない
- クローラーが見つからなければ行わない
- 行ったときは、Tauri のイベント `scheduled-fetch` で、積んだ作品の数か失敗の理由を画面に知らせる。画面は fetch all のボタンの横に、定期取得の時刻と、行ったことを表示する
- 画面に定期取得の設定を表示するため、コマンド `fetch_schedule` を置く

## 実装しないこと

- アプリが動いていないときに取得することはしない。OS の定期実行（launchd など）には登録しない
- 定期取得の設定を画面から変えることは、この ADR ではしない。管理画面を作るときに決め、保存の場所もそのときに決める
- 3:00 を過ぎていたときに、起きた後に行わないようにはしない

## テスト設計

- `src-tauri/src/schedule.rs` の単体テストで、次を確かめる
  - 前に見たときと今の間に 3:00 があれば行い、なければ行わないこと
  - 眠っている間に 3:00 を過ぎていれば行い、何日眠っていても 1 回であること
  - 時計が戻ったときは行わないこと
  - tokio の時間を止め、偽の壁時計を 1 分ずつ進めて、3:00 を越えたときに 1 回だけ行い、翌日に起きたときにもう 1 回行うこと
  - 無効なら何もしないこと
- 時刻を一時的に 2 分後に書き換えた debug ビルドの `.app` を、偽のクローラーを指定して起動し、その時刻を越えた後に fetch all が行われ、画面に時刻と行ったことが表示されることを確かめた。書き換えはコミットしない

## トレードオフ

- 1 分ごとに見るため、行うのは 3:00 から最大で 1 分ほど遅れる。その代わり、スリープを挟んでも取りこぼさない
- 起きた後に行うため、朝に計算機を開いたときに取得が始まり、しばらく相手のサイトにアクセスが続く
- アプリが動いていなければ行わないため、毎日の取得にはアプリを開いたままにしておく必要がある

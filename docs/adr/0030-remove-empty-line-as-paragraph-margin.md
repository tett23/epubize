# ADR 0030: 整形の設定の removeEmptyLine を、EPUB とプレビューの段落の余白で反映する

ステータス: 採択

## 文脈

ADR 0029 では、整形の設定のうち組方向だけを EPUB に使い、ほかの項目は使わないとした。
クローラーは本文を正規化して渡し、段落の間に 1 つだけある空行を消している（ADR 0009）。本文は 1 行が 1 段落の Markdown になり、作者の入れた空行は `<br>` だけの段落で表される。
作った EPUB を利用者が確かめたところ、removeEmptyLine が有効でも、行の間に空行が入って見えた。
EPUB のスタイルシートは段落の余白を指定しておらず、リーダーの既定の余白（1 行分）が段落ごとに入るためである。画面のプレビューは Tailwind CSS が段落の余白をなくしているため、空行が入らない。
kindlize の removeEmptyLine は、前後に文字のある 1 つだけの空行を消すものだった。本文から消す空行はクローラーが既に消しているため、epubize で同じ処理を重ねても何も変わらない。

## 実装すること

- removeEmptyLine を、段落の余白で反映する。ADR 0029 の「組方向のほかの項目は使わない」のうち、removeEmptyLine についてだけ改める。ADR 0029 は、そのほかの決定が生きているため、ステータスを採択のまま残す
- 有効（既定）なら、EPUB のスタイルシートに `p { margin: 0; }` を書き、行の間を空けない
- 無効なら、段落の余白を指定せず、リーダーの既定の余白で段落の間を空ける
- 作者の入れた空行（`<br>` だけの段落）は、どちらでも 1 行分残る
- 画面のプレビューも同じ見え方にする。無効なら段落の前後に 1 行分（`margin-block: 1em`）の余白を置く
- 整形の設定の値は画面と同じく読む。設定がない、読めない、型が合わないときは有効とする

## 実装しないこと

- 本文の Markdown から空行や段落を消したり、まとめたりはしない
- 組方向と removeEmptyLine のほかの項目は、この ADR でも使わない

## テスト設計

- `src-tauri/src/export_tests.rs`：整形の設定から removeEmptyLine を読むこと（既定、型の合わない値、JSON でない値）、有効なら段落の余白をなくすスタイルを書き、無効なら書かないこと
- E2E テスト：removeEmptyLine を無効にすると、プレビューの段落の前後に余白ができること
- 実際のアプリで EPUB を作り、スタイルシートに段落の余白の指定があることを確かめる

## トレードオフ

- 無効のときの段落の間の広さはリーダーに任せるため、リーダーによって変わる。その代わり、縦書きと横書きで向きを書き分けずに済む
- 名前は「空行を消す」だが、本文を変えずに見え方だけを変える。kindlize とは働きが違う

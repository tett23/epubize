# ADR 0003: GUI を Tauri で作り、データを epubize の SQLite に持つ

ステータス: 採択

## 文脈

epubize は EPUB の生成と、作品を管理する GUI を担う（ADR 0001）。
取得した作品のデータは、取得を担う非公開のクローラーではなく、利用する側が持つほうが、両者の結合が弱くなる。
クローラーにも確認用の SQLite があるが、それは検証のための仮置きであり、epubize が十分に動くようになった時点で消される。

## 実装すること

- GUI は Tauri で作る
- 作品、目次、各話の本文、挿絵などのデータは、epubize が持つ SQLite に保存する。置き場所は Tauri のアプリ用データ領域とする
- 挿絵は画像のバイト列を BLOB として SQLite に保存する
- クローラーから受け取るデータの形式は ADR 0005 に従う

## 実装しないこと

- クローラーの SQLite を読むことはしない。クローラーとのデータの受け渡しは ADR 0005 の形式だけで行う
- 挿絵をファイルとして別に保存することはしない

## テスト設計

- 方針の決定であり、この時点ではコードを伴わないため、テストはない
- スキーマを実装するときに、ADR 0005 の各レコードを保存して読み戻せることをテストする

## トレードオフ

- 挿絵を BLOB で持つため、データベースのファイルが大きくなる。その代わり、1 ファイルで作品一式を持ち運べる
- クローラーと epubize がそれぞれデータの形を持つため、受け渡し形式（ADR 0005）を両者で揃え続ける必要がある

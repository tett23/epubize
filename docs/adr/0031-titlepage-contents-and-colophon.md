# ADR 0031: EPUB に本の扉、目次のページ、章の扉、奥付を入れる

ステータス: 採択

## 文脈

ADR 0029 では、EPUB に話の本文だけを入れていた。読むときに、本の題名と著者、話の一覧、章の区切り、元の作品の情報が本の中にない。
epub-builder は、`meta/titlepage` を扉、`meta/colophon` を奥付として読み順に入れる。章のディレクトリの `index` は、部の扉（`bodymatter part`）として、そのディレクトリの最初の文書になり、目次の章の項目の行き先になる。
epub-builder は目次をナビゲーション文書と NCX にだけ書き、目次のページを読み順に入れない（epub-builder の仕様の「扱わないこと」）。
利用者は、扉は章の単位で付け、節（話）の単位では要らないとした。

## 実装すること

- 本の扉：`meta/titlepage.xhtml` に、題名と著者を置く
- 章の扉：章のディレクトリごとに `index.xhtml` を置き、章の名前を置く。話には扉を置かない。章のない話にも置かない
- 目次のページ：二話以上の本では、`body/` の最初に来る名前（`0000.xhtml` など、連番と同じ桁の 0）で、目次のページを置く。話の題名を並べ、章は章の扉を指す項目の下に入れ子にする。リンクは本文のファイルの元の名前（パーセントエンコードしたもの）で書き、epub-builder に書き換えさせる。一話だけの本には置かない
- 奥付：`meta/colophon.xhtml` に、題名、著者、掲載しているサイトの名前と URL（話だけの本なら話の URL）、収録した話（`第 1 話〜第 n 話のうち本文を取得した m 話`、一話なら `第 n 話`）、作った日と epubize を置く
- 作った日は、本を作ったときのローカル時刻の日付とする
- 扉、目次、奥付は XHTML の断片で書き、文字を実体参照に直す。スタイルシートに、縦書きと横書きの両方で使えるよう論理プロパティでスタイルを書く
- 著者が空なら、扉と奥付に著者を書かない

## 実装しないこと

- 目次のページに、ナビゲーション文書の `toc` の意味づけはしない。epub-builder が本文の文書に `bodymatter chapter` を付けるため、目次のページも本文の章として扱われる
- 話や、話の中の見出しには扉を置かない
- 表紙（`meta/cover`）は作らない
- 奥付にあらすじや取得した日時は書かない

## テスト設計

- `src-tauri/src/export_tests.rs`
  - 扉と奥付の中身（実体参照、著者のない本、サイトの名前、収録した話の書き方、作った日）
  - 章の扉を章のディレクトリごとに置き、章のない話と話の単位には置かないこと
  - 目次のページを本文の最初に置き、章を入れ子にし、リンクをパーセントエンコードすること。一話だけの本には置かないこと
  - zip の中身に扉、章の扉、奥付が入ること
- 開発用のデータの全ての作品から、本物の epub-builder で EPUB を作り、読み順が扉、目次、本文（章の扉を含む）、奥付になること、目次のページのリンクが本文の文書に書き換わること、landmarks に扉と奥付が入ることを確かめた

## トレードオフ

- 目次のページを本文の最初の文書にするため、landmarks の本文（`bodymatter`）は、最初の話ではなく目次のページを指す。リーダーの「本文の先頭へ」で目次のページに移る
- 目次のページはナビゲーション文書の目次にも「目次」として入る
- 奥付に作った日を書くため、同じ作品から作った EPUB でも、日が違えば中身が変わる
- 話数の多い作品では、目次のページが長くなる
